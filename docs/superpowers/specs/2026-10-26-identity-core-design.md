# AI 身份/人格核心 架构设计

- 日期：2026-10-26
- 状态：架构设计（待评审）
- 定位：一个**连续运行的「身份核心」**——维持稳定的自我定位（身份+性格+人格），
  对外部交流情境信息产生**清晰、可辨识、符合性格**的状态变化。
- 前提：不追求「自我意识」，只追求「连续的身份 + 符合性格的响应」。

## 0. 一句话

把已有的「多自我神经网络」包成一个能持续运行、能接外部事件、能查询状态、
能跨重启保持身份的程序——AI 的「我是谁」引擎。

## 1. 核心目标（四个能力）

1. **连续性**：持续运行，状态不丢，重启后「我还是我」。
2. **身份维持**：有稳定的「我是谁」，不随机漂移。
3. **性格/人格**：这个「我是谁」是有性格的（本我/超我/道家，6 维画像）。
4. **清晰响应**：外部信息 → 内部状态发生可辨识、可重复、符合性格的变化。

## 2. 四层架构

```text
外部交流情境信息（事件流）
        │
        ▼
┌─────────────────────────────────────────┐
│ 体验层  encode_event：外部信息 → 信号      │  （缺：需新建）
│   事件 → 情境偏置 / 输入扰动               │
└──────────────────┬──────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────┐
│ 状态层  多自我网络（已有）                 │
│   当前主导自我、活动水平、性格状态         │
│   （快变量，随事件变）                    │
└──────────────────┬──────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────┐
│ 记忆/连续性层  状态持久化 + 体验沉淀自传    │  （缺：需新建）
│   保证「连续不断」                        │
└──────────────────┬──────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────┐
│ 身份层  性格参数 + 人格配置（已有）        │
│   （慢变量，基本不变，重大事件才缓慢演化） │
└─────────────────────────────────────────┘
```

## 3. 各层职责与现状

| 层 | 职责 | 现状 | 要做的 |
| --- | --- | --- | --- |
| 身份层 | 性格参数、人格配置 | 已有 `persona.py` | 固化成持久配置 |
| 状态层 | 多自我网络、情境切换 | 已有 `multi_self.py` | 无需大改 |
| 记忆/连续性层 | 持久化、自传 | 缺 | 新建 |
| 体验层 | 事件 → 信号编码 | 缺 | 新建 |

## 4. 关键设计决策

### 4.1 外界信息交互端口（输入信息 + 输出意识状态）

身份核心对外是一个**对称的双向端口**，不是单向的「文本入口」：

```text
外界信息 ──输入──► [编码] ──► 身份核心 ──► [解码] ──► 意识状态 ──输出──► 外界
```

- **输入方向**：外界信息（文本 / 事件 / 信号，形态可插拔）统一编码为
  **事件流**，每条事件：

```text
Event = {
  type: str,        # 情境类型（危险/道德/平静/表扬/批评/...）
  intensity: float, # 强度（0~1）
  content: str,     # 可选，原始文本/内容（供记忆层记录）
}
```

事件类型映射到情境偏置（`multi_self.set_context`），驱动状态层。

- **输出方向**：身份核心的当前「意识状态」结构化输出，供外界读取/响应：

```text
ConsciousState = {
  dominant: str,       # 当前主导自我（id/superego/tao）
  activities: dict,    # 各自我活动率
  mood: str,           # 情绪倾向（由主导自我 + 活动率派生）
  context: dict,       # 当前情境偏置
}
```

文本形态的输入由「文本→事件」编码器（可规则可 LLM）转成事件；
意识状态若要以自然语言输出，由「状态→文本」解码器（可规则可 LLM）转成文字。
两者都是**可插拔的编解码器**，不是身份核心的一部分。

### 4.2 连续性：状态快照 + 自传日志

连续性分两层：

- **状态快照**：定期保存网络状态（各自我活动率、主导自我、情境）到磁盘，
  重启后恢复「快变量」。
- **自传日志**：把「重要体验」（事件 + 当时的自我状态）追加为不可变日志，
  形成「我经历过什么」的长期记录——这是「身份」的叙事底座。

性格参数（身份层）是慢变量，默认持久不变；只有「重大事件」（强度超过阈值）
才触发缓慢演化（对应人格随经历成长）。

### 4.3 身份维持：慢-快分离

- 慢变量（身份）：性格参数，持久、基本不变。
- 快变量（状态）：主导自我、活动水平，随事件变化。
- 这样「我是谁」（慢）稳定，而「我现在如何」（快）响应外部，二者不混淆。

## 5. 对外接口（未来 AI 可调用的面）

```python
core = IdentityCore(persona="tao", state_dir="data/identity")
core.process_event(Event(type="danger", intensity=0.8, content="..."))
state = core.query()      # 当前意识状态（主导自我、活动率、情绪倾向）
core.save()               # 持久化（也可自动定期）
core.load()               # 重启恢复

# 交互端口（M2/M4）：
state = core.interact(raw_input)   # 输入外界信息，输出意识状态
```

## 6. 里程碑

1. **M1 最小身份核心**：`IdentityCore` 类，跑通「事件→状态→查询→保存→恢复」闭环。
2. **M2 连续性**：状态快照 + 自传日志，跨重启保持身份。
3. **M3 人格演化**：重大事件触发性格参数缓慢演化。
4. **M4 交互端口**：可插拔「信息→事件」编码器 + 「状态→输出」解码器
   （规则版，后续可换 LLM），实现输入信息、输出意识状态的双向交互。

## 7. 非目标

- 不追求自我意识、主观体验。
- 不要求「文本对话」能力（M4 只做可插拔的文本→事件编码，不做生成式对话）。
- 不做多机分布式。
- 不改已有的网络动力学（状态层复用，只补体验层和记忆层）。

## 8. 与已有资产的关系

本设计是「延续」而非「重写」：

- 复用 `balanced_network.py`（身体）、`multi_self.py`（多自我+情境）、
  `persona.py`（性格）。
- 新建 `identity_core.py`（组装四层）、`event.py`（事件编码）、
  `continuity.py`（快照+自传）。
