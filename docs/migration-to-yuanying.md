# 移植分析：把「bioelectric-emergence」应用到「人造元婴」
- 日期：2026-10-29
- 性质：对照分析 + 移植建议（不写代码、不改人造元婴，仅供决策）

## 0. 结论先行
人造元婴**已经有** OCEAN 人格引擎、身份锚、自传、元认知记忆闭环，
且质量高、有审计。我们项目里「OCEAN 人格 + 规则演化」这部分**重复了**，
不应移植（否则会变成它纲领明令禁止的「补丁式模块」）。

真正值得移植的，是它**缺**的四个能力：
1. 情绪维度（valence/arousal）
2. 意识状态维度（self_clarity/agency）
3. 多自我共存结构（本我/超我/道家 + 情境切换）
4. LLM 蒸馏的「语言 → 人格」感知入口

## 1. 两项目对照
| 能力 | bioelectric-emergence（本项目） | 人造元婴 |
| --- | --- | --- |
| 人格维度 | 9 维（情绪2+性格5+意识2） | 5 维（仅 OCEAN） |
| 人格演化 | 涌现式（SNN 学习痕迹） | 规则式（EVENT_RULES，有审计） |
| 身份锚 | 无（哲学核心弱） | 有（我是谁/从哪来/往哪去，只读） |
| 自传/记忆 | 有（JSONL） | 有（更完善，含元认知维护） |
| 多自我 | 有（本我/超我/道家） | 无 |
| 语言感知 | 有（LLM 蒸馏 9 维模型） | 无（事件规则，无语言入口） |
| 身体 | 平衡脉冲网络 | 分布式神经元网络（更成熟） |

## 2. 建议移植的四个能力（按优先级）
### 优先级 1：情绪维度（valence/arousal）
人造元婴的 OCEAN 是「慢变量性格」，没有「快变量情绪」。
它缺一个「此刻的情绪状态」，而情绪正是「清晰响应外部情境」所必需的。
移植方案：把 valence/arousal 作为 Persona 的**即时情绪快照**，与 OCEAN 性格并列，
由情境事件即时更新、随 OCEAN 缓慢回落。

### 优先级 2：意识状态维度（self_clarity/agency）
人造元婴有身份锚（哲学核心），但缺少「自我清晰度」「主体性」这两个**可观测的
动态意识状态**。可作为身份锚与人格之间的「当下自知程度」指标，供元认知使用。

### 优先级 3：多自我共存（本我/超我/道家）
人造元婴是「单一人格画像」。移植「多个自我侧面 + 情境切换 + 互相制衡」，
能让它在不同情境表现出不同侧面（危险→应激、平静→从容），而非单一风格。
但改动最大，需谨慎——它可能触及人造元婴「发育 vs 补丁」的判据。

### 优先级 4：LLM 蒸馏的语言→人格入口
人造元婴的人格由事件规则驱动，没有「从自然语言推断情绪/人格」的能力。
移植 LLM 蒸馏的 9 维模型，可让它能**从对话文本直接感知情绪/人格**，
补上「语言理解」这一入口。需注意它是否接受引入 LLM 蒸馏组件。

## 3. 不建议移植的
- OCEAN 人格引擎：重复。
- 规则演化（evolve_ocean/EVENT_RULES）：重复。
- 平衡脉冲网络（balanced_network）：人造元婴有更成熟的分布式神经元网络，
  强行替换违反其纲领。
- SNN 涌现式人格：与其「发育而非补丁」哲学存在张力，需单独论证。

## 4. 风险与注意事项
1. 人造元婴纲领明确「不引入补丁式模块冒充发育」——任何移植都必须证明
   是「发育」而非「补丁」，否则违背其顶层纲领。
2. 人格不能越权到安全边界——人造元婴的 Persona 刻意与工具权限/本能内核解耦，
   移植的情绪/多自我也必须保持这一边界。
3. 移植顺序建议 1→2→4→3，先补「维度」再动「结构」，风险递增。

## 5. 下一步
本报告仅供决策。若决定移植，建议从「优先级 1：情绪维度」开始，做最小侵入的
独立设计稿（放人造元婴的 docs/superpowers/specs/ 下），经其纲领判据评审后再实现。
